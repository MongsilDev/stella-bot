# 스텔라봇 (stella-bot) 설계

Discord 채널 1개에서 한국어·일본어 사용자가 자유롭게 대화할 수 있도록 실시간 상호 번역을 제공하는 봇.

## 목표

- 지정된 채널 1개에서 KO↔JA 자동 번역
- 번역문은 원 작성자의 닉네임·아바타로 표시되어 대화 흐름이 자연스러움
- 답장(reply) 관계가 번역문에서도 유지됨
- 원본 수정·삭제가 번역문에 반영됨

## 스택 / 배포

| 항목 | 선택 |
|------|------|
| 언어 | Python 3.12 |
| Discord | discord.py >= 2.7.1 |
| 번역 | DeepL API Free (월 50만 자) |
| HTTP | httpx |
| 저장소 | aiosqlite (메시지 ID 매핑) |
| 장애 추적 | Sentry |
| 배포 | GitHub private 레포 → NAS python 컨테이너, PMC 프로세스 `stella-bot`, scp 전송 |

## 메시지 플로우

```
on_message
→ 필터: 봇/웹훅 메시지, 대상 외 채널, 빈 텍스트 제외
→ 언어 감지 (휴리스틱)
→ 마스킹: 커스텀 이모지·멘션·채널링크·코드블록을 토큰으로 치환
→ DeepL 번역
→ 복원: 토큰을 원래 값으로 되돌림
→ 웹훅 게시: 작성자 닉네임 + 아바타, allowed_mentions=none
→ message_map에 원본↔번역 ID 저장
```

## 언어 감지

API 호출 없는 문자 범위 휴리스틱.

- 한글(가-힣, 자모) 포함 → KO→JA
- 가나(ひらがな·カタカナ) 포함 → JA→KO
- 한글·가나 둘 다 포함 → 문자 수가 많은 쪽을 원문 언어로 판정
- 한자만 있음 → JA→KO (한국어 채팅에서 한자 단독 사용은 거의 없음)
- 그 외(영어 등)·첨부만 있는 메시지 → 번역 스킵

## 리플라이 매핑

웹훅 메시지는 Discord API 제약상 진짜 reply(message_reference)가 불가하다. 인용줄로 대체한다.

- DB 스키마: `message_map(orig_id, trans_id, channel_id, author_id, direction, created_at)` — orig_id, trans_id 양쪽 인덱스
- 사용자가 reply한 대상이 원문이든 번역문이든 매핑을 조회해, **번역 출력 언어와 같은 쪽 메시지**로 점프링크를 건다
  - 예: Taro가 일본어 번역문에 reply → 한국어 번역문의 인용줄은 한국어 원문으로 점프
- 인용줄 형식: `-# ↩︎ [작성자 표시명](점프링크)` 다음 줄에 번역문
- 매핑에 없는 메시지(봇 도입 전 메시지 등)에 reply한 경우 → 그 메시지 자체를 링크

## 수정 / 삭제 동기화

- 원본 수정(`on_raw_message_edit`) → 재번역 후 웹훅 메시지 edit
- 원본 삭제(`on_raw_message_delete`) → 번역문 삭제
- 이미 삭제된 메시지 등 레이스 상황 → NotFound 무시

## 콘텐츠 처리 규칙

- 커스텀 이모지 `<:name:id>`, @멘션, #채널: 마스킹 후 복원. 번역문에서 멘션 알림이 울리지 않도록 `allowed_mentions=none`
- 코드블록(```)·인라인코드(`): 번역하지 않고 그대로 통과
- 첨부파일·이미지: 캡션 텍스트만 번역, 캡션 없으면 스킵 (원본이 바로 위에 있으므로 재첨부 불필요)
- 스티커·보이스 메시지·임베드: 무시
- 번역 결과 2000자 초과 → 분할 게시

## 에러 처리

- DeepL 호출 실패 → 지수 백오프로 3회 재시도 → 최종 실패 시 원본 메시지에 ⚠️ 리액션 (번역 안 됐다는 신호)
- 월 한도 초과(HTTP 456) → ⚠️ 리액션 + Sentry 알림
- 웹훅이 삭제된 경우 → 재생성 (봇에 Manage Webhooks 권한 필요)
